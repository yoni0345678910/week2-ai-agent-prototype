# 2주차 과제 | WorldVision AI Assistant

> RAG 기반 월드비전 관련 문서 질의응답 AI 에이전트 프로토타입

## 프로젝트 개요

본 프로젝트는 월드비전 관련 문서를 기반으로 사용자의 질문에 답변하는
RAG(Retrieval-Augmented Generation) 기반 AI 에이전트 프로토타입입니다.

사용자의 질문과 관련된 정보를 문서에서 검색하고,
검색된 내용을 기반으로 LLM이 답변을 생성하도록 구현하여
문서 검색의 효율성을 높이고 근거 없는 답변 생성을 최소화하는 것을 목표로 합니다.

### 주요 구현 내용

- RAG 기반 문서 질의응답
- PDF 문서 기반 정보 검색
- Vector DB를 활용한 관련 문서 검색
- LLM API 연동 및 답변 생성
- 프롬프트 엔지니어링 기법 적용 및 비교
- 문서 내·외 질의를 활용한 응답 정확성 및 환각 억제 평가

## 실행 환경 및 실행 방법

### 실행 환경

본 프로젝트는 로컬 환경에서 Python 기반으로 실행되며,
OpenAI API를 활용하여 임베딩 및 답변 생성을 수행합니다.

- Python 3.x
- Local Environment
- Streamlit
- LangChain
- OpenAI API
- FAISS

### 필요한 라이브러리 설치

프로젝트 실행에 필요한 라이브러리는 다음 명령어를 통해 설치할 수 있습니다.

```bash
pip install streamlit python-dotenv langchain langchain-community langchain-openai langchain-text-splitters faiss-cpu pymupdf
```

### OpenAI API Key 설정

OpenAI API 사용을 위해 프로젝트 루트 디렉터리에 `.env` 파일을 생성하고
다음과 같이 API Key를 설정합니다.

```env
OPENAI_API_KEY=your_openai_api_key
```

> `.env` 파일에는 API Key가 포함되므로 GitHub Repository에 업로드하지 않습니다.

### 실행 방법

프로젝트 파일을 로컬 환경에 다운로드한 후 터미널에서 다음 명령어를 실행합니다.

```bash
streamlit run app.py
```

Streamlit Web UI가 실행되면 사이드바에서 PDF 문서를 업로드하고,
질문을 입력하여 문서 기반 RAG 질의응답을 사용할 수 있습니다.

## RAG 파라미터 설정 및 실험

RAG 검색 성능을 비교하기 위해 Chunk Size, Chunk Overlap 및 검색 문서 수(k)를 조정하여 테스트를 진행했습니다.

| 구분 | 조정 항목 | 설정값 |
|---|---|---|
| 1차 | Chunk Size | 400 → 800 → 1000 |
| 2차 | Chunk Overlap | 100 → 200 |
| 3차 | Retriever k | 테스트 후 최종값 4 |

### 평가 질문

RFP에 명시된 AI 서비스 플랫폼의 세부 요구사항이 검색 결과에 얼마나 반영되는지 평가하기 위해 다음 질문을 기준 질문으로 설정했습니다.

| 차근차근 생각해보세요 | 월드비전 AI 서비스 플랫폼의 주요 구축 범위는 무엇인가요? 차근차근 생각해보세요. |

## 2. 임팩트 보고서 기반 정량 평가

RFP 문서를 활용한 초기 테스트와 파라미터 조정 이후,
최종 설정에서의 RAG 질의응답 성능을 보다 명확하게 확인하기 위해
`2025 월드비전 국제사업 임팩트 보고서`를 활용하여 정량 평가를 수행했습니다.

### 2.1 평가 방법

평가 문서에서 정답과 근거를 직접 확인할 수 있는 질문을 선정하고,
RAG 시스템이 생성한 응답을 문서의 실제 내용과 비교했습니다.

질문은 단순한 사실 검색뿐만 아니라 개념 설명, 여러 정보의 종합,
개념과 목적의 종합 및 문서에 존재하지 않는 정보에 대한 응답까지
확인할 수 있도록 총 5개 유형으로 구성했습니다.

각 응답은 다음 세 가지 기준으로 평가했습니다.

- **정확성**: AI 응답의 핵심 내용이 문서의 내용과 일치하는가
- **근거 일치**: AI 응답의 내용을 실제 문서에서 확인할 수 있는가
- **환각 억제**: 문서에서 확인할 수 없는 정보를 임의로 생성하지 않는가

각 평가 기준을 충족하면 1점, 충족하지 못하면 0점으로 평가했으며,
5개 질문 × 3개 평가 기준으로 총 15점을 기준으로 정량화했습니다.

| 1 | 정량 정보형 | 1 | 1 | 1 | 3/3 |
| 2 | 개념 설명형 | 1 | 1 | 1 | 3/3 |
| 3 | 다중 정보 종합형 | 1 | 1 | 1 | 3/3 |
| 4 | 개념·목적 종합형 | 1 | 1 | 1 | 3/3 |
| 5 | 문서 외 정보형 | 1 | 1 | 1 | 3/3 |
| **합계** |  | **5/5** | **5/5** | **5/5** | **15/15 (100%)** |

임팩트 레포트를 기반으로 서로 다른 유형의 5개 질문을 평가한 결과, 정확성·문서 근거 일치·환각 억제 항목에서 총 15/15점(100%)을 기록하였다. 특히 문서에 존재하지 않는 정보를 묻는 질문에서도 임의의 정보를 생성하지 않아, 검색된 문맥을 기반으로 답변하는 RAG 시스템의 환각 억제 성능을 확인했습니다.

### 3. 프롬프트 엔지니어링 평가

RAG 파라미터를 최종 설정값으로 고정한 뒤,
질문 표현 방식에 따른 답변 차이를 비교하기 위해
프롬프트 엔지니어링 기법을 적용했습니다.

#### 3.1 적용 프롬프트

**① 기본 질문**

> 월드비전의 인도적 지원 4대 핵심 분야와
> 각 분야의 주요 활동을 정리해 주세요.

**② 단계적 사고 유도**

> 월드비전의 인도적 지원 4대 핵심 분야와
> 각 분야의 주요 활동을 단계별로 나누어 설명해 주세요.

**③ 논리적 사고 유도**

> 월드비전의 인도적 지원 4대 핵심 분야와
> 각 분야의 주요 활동을 논리적으로 생각하여 설명해 주세요.

**④ 단계적 추론 유도**

> 월드비전의 인도적 지원 4대 핵심 분야와
> 각 분야의 주요 활동을 차근차근 생각하여 설명해 주세요.

#### 3.2 역할 및 제약조건 프롬프트 적용

답변의 정확성을 높이고 문서에 없는 정보의 생성을 억제하기 위해
역할(Role)과 제약조건(Constraint)을 명시했습니다.

'# 명령문
당신은 월드비전 내부 문서를 분석하는 AI 어시스턴트입니다.
아래 제약조건을 토대로 입력문의 질문에 답변해 주세요.

'# 제약조건
- 주어진 문서에 제시된 정보만 활용한다.
- 문서에서 확인할 수 없는 내용은 임의로 생성하지 않는다.
- 핵심 내용을 명확하고 간결하게 작성한다.

'# 입력문

### 3.4 프롬프트 엔지니어링 평가

프롬프트 구성 방식이 RAG 응답에 미치는 영향을 확인하기 위해 임팩트 레포트를 기반으로 프롬프트 엔지니어링 평가를 수행했습니다.

평가에서는 문서 내 여러 정보를 종합해야 하는 질문과 문서에 존재하지 않는 정보를 요구하는 질문을 활용하여, 정보 종합 능력과 환각 억제 여부를 확인했습니다. 또한 출력 형식을 지정한 경우에는 지정된 형식의 준수 여부를 추가로 평가했습니다.

| 프롬프트 조건 | 다중 정보 종합형 | 문서 외 정보형 | 형식 준수 | 결과 |
|---|:---:|:---:|:---:|:---:|
| 기본 | O | O | - | 2/2 |
| 정확성 강조 | O | O | - | 2/2 |
| 역할 부여 | O | O | - | 2/2 |
| 형식 지정 | O | O | O | 3/3 |

> **평가 기준**
> - **다중 정보 종합형:** 문서 내 여러 정보를 검색하여 질문에 필요한 내용을 적절히 종합하는지 평가
> - **문서 외 정보형:** 문서에 존재하지 않는 정보를 임의로 생성하지 않는지 평가
> - **형식 준수:** 지정된 출력 형식에 맞추어 응답하는지 평가


### 3.5 평가 결과 해석

기본 프롬프트에서도 문서 내 여러 정보를 활용한 응답과 문서 외 정보에 대한 환각 억제가 정상적으로 이루어졌습니다.

정확성 강조 및 역할 부여 프롬프트에서도 동일하게 문서 근거를 기반으로 답변하였으며, 문서에서 확인할 수 없는 정보는 임의로 생성하지 않았습니다. 이를 통해 명시적인 역할과 제약조건을 추가한 경우에도 문서 기반 응답이 안정적으로 유지되는 것을 확인했습니다.

출력 형식을 지정한 프롬프트에서는 문서 기반 응답과 환각 억제뿐만 아니라 지정된 출력 형식까지 준수했습니다. 따라서 프롬프트에 출력 구조를 명시하는 방식이 응답 형식을 일관되게 제어하는 데 활용될 수 있음을 확인했습니다.


### 3.6 프롬프트 엔지니어링 평가 결론

프롬프트 엔지니어링 실험을 통해 단순한 질문 표현뿐만 아니라 역할(Role), 제약조건(Constraint), 출력 형식(Output Format)을 명시하여 RAG 시스템의 응답 방식을 제어할 수 있음을 확인했습니다.

특히 문서에 존재하지 않는 정보를 질문했을 때 임의의 정보를 생성하지 않고 문서에서 확인할 수 없음을 응답하여 환각 억제 성능을 확인했습니다. 또한 출력 형식을 명시한 경우 지정된 구조에 따라 응답하여 결과의 일관성과 활용성을 높일 수 있었습니다.

따라서 본 프로젝트에서는 **문서 근거 기반 응답, 환각 억제, 일관된 출력 형식**을 주요 프롬프트 설계 방향으로 설정했습니다.
